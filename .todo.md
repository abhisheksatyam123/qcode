## Systems

### Goal
Port opencode's essential modules (tools, chat, system prompt) into qcode's C++ TUI
with proper chat window and slash command behavior matching opencode.

### Architecture
```
include/ai/tui/
  chat.h              run_llm_generation() signature
  commands.h          SlashCommand struct, builtin_slash_commands(), handle_slash_command()
  config.h            get_antigravity_token(), load_providers_from_config()
  state.h             ModelInfo, ProviderInfo, ChatState
  system_prompt.h     SystemPrompt::build_default() (identity + tool contract)
  tools.h             ToolDescriptor, ToolConfig, Tools::build_definitions()
  views.h             Colour palette, render_logo(), render_view()

src/tui/
  main.cpp            Entry: screen, input, slash popup, submit handler
  chat.cpp            LLM generation thread (tool+streaming paths)
  commands.cpp        Slash command dispatch (model, provider, system, tools, clear, help)
  config.cpp          Provider config loading (ordered_json for insertion order)
  system_prompt.cpp   System prompt builder (opencode _shared/base style)
  tools.cpp           Tool definitions, descriptions, formatting
  views.cpp           UI rendering (logo, home, chat view, slash popup with categories)
```

### Changes made
- Slash commands use SlashCommand struct with name, title, description, category, aliases
- /model searches across ALL providers (not just current)
- /model provider/model supports explicit provider+model syntax
- /provider switches provider and resets to first model
- Slash popup shows commands grouped by category with descriptions
- /help shows categorized command list
- Config uses ordered_json to preserve JSON insertion order
- Fixed /v1 double-encoding bug (strip trailing /v1 from config URLs)
- System prompt follows opencode _shared/base.md pattern
- Tool definitions use SDK's BashTool and TaskTool directly

### Status
- Build: clean
- Slash commands: categorized popup with descriptions
- Model selection: cross-provider search with provider/model syntax
- API routing: opencode/antigravity/openrouter all working
